# 条款重排校稿台

本地运行的条款校稿工具：粘贴一份带编号的条款文本，在页面上**编辑正文、调整顺序、删除条款、合并条款、拆分条款、复制条款**，
随时预览连续重排后的新编号与引用；修复所有失效引用后，才能下载与预览完全一致的纯文本。
成功导入后可随时**对照原稿**，只列发生变化的条款（新增 / 删除 / 正文改动 / 移动）；
也可以勾选若干条款，把它们连同直接、间接引用的全部现存条款**导出为独立编号的摘录**。
校稿中途可点**「保存存档」**把整份快照（原稿基线、当前顺序、正文与身份上界）存入服务端 SQLite，
刷新页面或重建容器后点**「恢复存档」**即可继续校订。

- 后端：Python + FastAPI（校稿接口无状态，草稿在浏览器内存；存档单独存 SQLite 共享槽）
- 前端：原生 HTML / CSS / JavaScript，无框架、无构建步骤
- 未保存存档的草稿仍只在浏览器内存：刷新或关闭页面即丢失；存档经数据卷持久化，重建容器后仍在

## 启动（一条命令）

```bash
docker compose up --build
```

启动后访问：

> **http://localhost:8000**

停止：在终端按 `Ctrl+C`（如需后台运行用 `docker compose up --build -d`，停止用 `docker compose down`）。

存档数据存放在 SQLite 数据库（容器内 `/app/data/archive.db`），由 Compose 命名数据卷
`archive-data` 持久化：**重建容器（`docker compose up --build`）后存档仍在**；
`docker compose down -v` 会连同数据卷一起删除存档。数据库文件与表在首次访问存档接口时
自动创建，无需手动初始化。

## 输入格式

导入区每行一条，共 **2～40 行**：

```
编号|正文
```

- 编号必须是正整数，从 **1 开始连续排列**，不可重复、不可缺号。
- 正文内用 `[[编号]]` **显式引用**其他条款，例如 `按 [[1]] 验收`；
  引用编号两侧不可有空格（`[[ 1 ]]` 视为格式错误）。
- 每条条款只占**一行**（正文内部不能换行）；竖线只在第一个处分隔，正文里可以再含 `|`。
- 允许引用自身。

以下任意问题都会导致**整份拒收**，并逐行列出原因：格式错误、编号重复/不连续、
引用无目标（编号超出范围）、空行或空正文、未闭合的 `[[`。

## 使用规则（引用如何绑定）

- 导入时，正文里的 `[[编号]]` 立即绑定到该编号对应的**那条原始条款**（内部使用稳定标识，
  显示编号会随重排实时更新）。
- 编辑某条正文时，新输入的 `[[数字]]` 按**点击保存那一刻**页面上显示的编号绑定。
  因此之后无论怎样拖拽重排，引用都不会转指“占用了旧号码”的另一条条款。
- 保存时同样校验：正文不能为空、不能跨行、引用编号必须在当前范围内，否则拒绝保存并提示。
- 删除被其他条款引用的条款时，会提示影响范围；删除后，指向它的位置标为
  **`[[原N?]]`（红色失效标记）**，顶部横幅和条款卡片同时标出引用来源（第几条/原第几条）
  与失效位置。
- 存在失效引用期间，**「下载纯文本」按钮禁用**，导出接口也会拒绝（HTTP 409）。
  编辑对应条款，把失效标记改成有效的 `[[当前编号]]` 或删掉该标记并保存，即完成修复。
- **合并条款**：勾选两条不同条款后点工具栏「合并所选」。系统按**当前显示顺序**把两条正文用
  全角分号「；」连接（较前正文；较后正文）；合并结果占据较前条款的位置并**沿用它的身份**，
  较后条款移除，其余条款相对顺序不变。原来指向较后条款的所有引用——包括两条待合并正文里的
  引用——都改指合并结果；指向较前条款及其他条款的引用不变；合并前已失效的引用仍保持失效。
  合并后编号自动重排，之后继续编辑或拖拽重排，引用也不会转指。正在编辑正文时须先**保存或取消**
  才能合并；合并失败（如服务端校验不通过）不会改动草稿。
- **拆分条款**：点条款卡片上的「拆分」，在**已保存正文**的字符分界处点击竖线放置拆分点，
  并选择原来指向本条的**全部引用（含本条自引用）落到前段还是后段**，再点「确认拆分」。
  分界**不能切开有效或失效引用标记**（标记整体归入某一段），**两段都不能只含空白**，
  其余字符原样保留（含分界两侧的空白）。**前段沿用原身份，后段获得本草稿从未用过的新身份**——
  被删除或合并移除的身份不会复用，已有失效引用不会因此复活；两段内的原有引用保持绑定，
  只有指向被拆条款的引用统一改指所选段。新条款**紧跟前段**，其余条款顺序不变；
  拆分后可继续编辑、重排、合并与再拆分，列表、引用跳转、预览与下载同步更新。
  条款总数达 40 条时不能再拆分；取消、拆分请求失败（服务端校验不通过或断网等异常）
  都不会改动草稿，分界与引用落点保留可重试；拆分成功但随后预览失败时，已拆分结果
  保留不回滚，点「重试预览」恢复一致列表后即可继续操作，预览恢复前禁止下载、
  不能用旧编号跳转（详见下节）；正在编辑正文时须先**保存或取消**才能拆分。
- **复制条款**：勾选一条或多条条款后点工具栏「复制所选」。系统按**当前显示顺序**为
  所选条款生成可独立编辑的副本，整组副本插在所选最后一条之后；原条款的正文、身份、
  相对顺序与引用均不变。副本正文中**指向组内条款的引用（含自引用）改指相应副本**，
  指向组外条款的引用保留原目标，已失效引用仍保持失效；副本取得**高于已用身份上界**的
  全新身份（与拆分共用同一上界，被删除或合并移除的身份不会复用），后续编辑、重排、
  合并、拆分仍按稳定身份绑定。正在编辑正文或拆分选择未结束时须先**保存或取消**才能复制；
  复制后总数超过 40 条会被拒绝；复制失败（服务端校验不通过或断网等异常）不会改动草稿，
  已勾选的条款保持不变，可修正后重试。
- 右侧预览与下载文件由服务端同一套解析逻辑生成，格式均为 `新编号|正文`，保证完全一致。
- **导出摘录**：勾选一条或多条条款后点工具栏「导出摘录」。系统按**当前已保存草稿**把勾选条款
  及其**直接、间接引用的全部现存条款**（自引用、循环与重复引用只收录一次）收进一份可独立阅读的
  摘录：摘录按草稿当前顺序**从 1 连续编号**，正文中的引用改用**摘录内编号**，其余字符不变。
  页面展示「摘录编号 ↔ 草稿编号 ↔ 稳定身份」映射与摘录文本，点「下载摘录」保存为纯文本。
  收录范围内存在失效引用时**整份拒绝**（HTTP 409），并列出来源稳定身份与缺失目标；
  **范围外的失效引用不阻止摘录，也不解除整稿「下载纯文本」的限制**。摘录是只读操作，
  不改变草稿、原稿基线、身份上界与引用绑定；正在编辑正文或拆分选择未结束时须先**保存或取消**；
  改稿、切换勾选或重新导入会立即清空摘录结果，迟到响应不会恢复结果、提示或触发下载。

## 校稿存档

工具栏「保存存档」把**共享槽的完整快照**写入服务端 SQLite（自动建库建表，Compose 数据卷持久化）：
**原稿基线、当前顺序、内部正文与已用身份上界**，不含勾选、编辑中正文或拆分选择等临时状态。
刷新页面、关闭再打开或重建容器后，点「恢复存档」（校稿台工具栏或导入页均可）即可继续校订。

- **保存**：点「保存存档」，携带最近读取或保存成功得到的版本整份写入，成功后版本加 1；
  首次保存（尚未取得版本）时会先自动读取一次槽内版本，再据此写入。
  工具栏状态随草稿变化提示「尚未保存存档 / 有未存档的修改 / 已存档（版本 N）」。
  **保存期间可继续改稿**：回执只确认提交当刻的快照，此后又有修改的仍提示未存档，需再次保存。
  **保存期间也允许重新导入或恢复存档**：整个保存动作（含首次保存前的预读取）归属发起时的
  草稿——换稿后迟到的预读取无论成功还是失败都直接作废，不会触发后续写入，也不会改动新稿的
  版本、未存档标记、提示或新一次保存的等待状态；换稿后可再次正常保存。
- **冲突（HTTP 409）**：服务端存档已被别处更新时，本次保存不写入，**本地草稿保留、不自动覆盖**；
  横幅提示并可点「读取最新版本」——读取后再保存将覆盖服务端该版本存档，
  或点「恢复存档」用服务端存档替换本地稿。
- **恢复**：先读取最新版本，**确认后整份替换当前草稿**（未存档的修改将丢失）。
  **未保存编辑、拆分选择或写稿未结束时不可恢复**（按钮禁用）。恢复成功后基线、顺序、正文与
  身份上界整份安装，旧在途请求一律隔离；**失效引用与身份上界一并恢复**，继续拆分、复制不会
  复用旧身份。恢复后自动重算预览与对照；**预览失败保留恢复稿、可重试**，预览恢复前禁止
  旧编号跳转与下载（与既有预览失败规则一致）。
- 存档校验沿用草稿校验：基线与现稿均须合法，**身份上界须覆盖基线、现稿及失效引用中的
  全部身份号**；非法快照（422）或写入失败（500）时旧存档一律保留。

HTTP 接口：`GET /api/archive` 读取共享槽（空槽版本为 0、快照为 `null`），
`PUT /api/archive` 携带版本整份写入（仅版本匹配时写入并加 1，冲突 409 并附当前版本）。
请求示例：

```bash
# 读取（空槽返回 {"version": 0, "snapshot": null}）
curl http://localhost:8000/api/archive

# 保存：version 为最近读取或保存成功得到的版本
curl -X PUT http://localhost:8000/api/archive \
  -H 'Content-Type: application/json' \
  -d '{
    "version": 0,
    "snapshot": {
      "baseline": {
        "order_ids": ["c1", "c2", "c3"],
        "clauses": [
          {"id": "c1", "body": "甲方在七日内交付设备"},
          {"id": "c2", "body": "乙方按 [[c1]] 验收后付款"},
          {"id": "c3", "body": "争议提交仲裁"}
        ]
      },
      "order_ids": ["c1", "c2", "c3"],
      "clauses": [
        {"id": "c1", "body": "甲方在七日内交付设备"},
        {"id": "c2", "body": "乙方按 [[c1]] 验收后付款"},
        {"id": "c3", "body": "争议提交仲裁"}
      ],
      "id_counter": 3
    }
  }'
# → {"version": 1}；再用 version 0 保存同一槽将返回 409 及当前版本
```

## 原稿对照

点工具栏「对照原稿」展开 / 收起对照面板（再次点击即收起）。**成功导入那一刻的原稿作为不可变基线**
保留在浏览器内存中，此后每次对照都把它与**当前已保存草稿**按稳定身份逐条比较：

- 只列发生变化的条款，标签为 **新增、删除、正文改动、移动**，标签可并存；没有任何变化时显示「无变更」。
  每条展示**原编号、现编号与两版正文**；现存条款按当前顺序排列，删除条款排在最后、按原顺序排列。
- **正文改动按内部引用绑定比较**：重排后引用显示的数字会变，但仍指向同一条款，不算正文改动；
  正文文字或引用指向的稳定身份变了才算。
- **移动只标记参与原稿中仍存在条款“先后颠倒”的条款**；删除条款或拆分插入新条款造成的纯编号平移
  （其余条款相对先后未变）不算移动。
- **合并**记保留身份的正文改动与另一身份的删除；**拆分**记前段（沿用原身份）的正文改动与
  后段（新身份）的新增；**复制**记各副本（新身份）的新增，原条款不变。
- 正文本身未变、但其中某条引用因目标条款被删除而**由有效变失效**时，在「正文未变但引用由有效变失效」
  一节另列：引用来源条款的原/现编号、稳定身份、失效标记 `[[原N?]]` 及其在正文中的位置（1 起、按字符计），
  并并排显示两版正文。
- 对照始终基于**已保存草稿**：取消编辑、保存失败都不改变对照；**预览刷新失败时仍可按已提交草稿对照**
  （对照与预览相互独立，不影响跳转、下载等既有规则）。改稿后旧对照立即失效（内容置灰提示），
  迟到响应不会覆盖新结果；**重新导入清空基线**，下一次成功导入再建立新基线。

HTTP 接口 `POST /api/diff` 接收基线（`baseline`）与当前草稿（`current`），两部分都沿用现有草稿结构
（`{order_ids, clauses}`，正文为内部形态 `[[c3]]`），返回对照结果；**接口不回退、不修改任何一份草稿**，
既有接口、引用跳转与下载规则保持不变。请求示例：

```bash
curl -X POST http://localhost:8000/api/diff \
  -H 'Content-Type: application/json' \
  -d '{
    "baseline": {
      "order_ids": ["c1", "c2", "c3"],
      "clauses": [
        {"id": "c1", "body": "甲方在七日内交付设备"},
        {"id": "c2", "body": "乙方按 [[c1]] 验收后付款"},
        {"id": "c3", "body": "争议提交仲裁"}
      ]
    },
    "current": {
      "order_ids": ["c1", "c3"],
      "clauses": [
        {"id": "c1", "body": "甲方在七日内交付设备"},
        {"id": "c3", "body": "争议提交仲裁"}
      ]
    }
  }'
```

返回（字段含义：`baseline_no/current_no` 为原/现显示编号、`baseline_text/current_text` 为
两版解析后正文、`tags` 为并存标签；删除 c2 后其引用来源另列在 `invalid_refs`）：

```json
{
  "items": [
    {
      "id": "c2", "original": 2,
      "baseline_no": 2, "current_no": null,
      "baseline_text": "乙方按 [[1]] 验收后付款", "current_text": null,
      "tags": ["deleted"]
    }
  ],
  "invalid_refs": [],
  "has_changes": true
}
```

## 复制接口示例

HTTP 接口 `POST /api/duplicate` 接收当前草稿（`order_ids` / `clauses`，正文为内部形态
`[[c3]]`）、所选身份（`selected_ids`）与已用身份上界（`next_id`），返回新草稿及更新后的上界；
未选择、选择重复或不存在、复制后超过 40 条、上界过期（新身份与现有条款或既有引用冲突）
都会返回 422 且不改动草稿。服务地址与页面相同（本地默认为 `http://localhost:8000`）。请求示例：

```bash
curl -X POST http://localhost:8000/api/duplicate \
  -H 'Content-Type: application/json' \
  -d '{
    "order_ids": ["c1", "c2", "c3"],
    "clauses": [
      {"id": "c1", "body": "甲方在七日内交付设备"},
      {"id": "c2", "body": "乙方按 [[c1]] 验收后付款"},
      {"id": "c3", "body": "争议解决见 [[c2]]"}
    ],
    "selected_ids": ["c2", "c3"],
    "next_id": 3
  }'
```

返回（副本 c4 复制 c2、 c5 复制 c3，整组插在所选最后一条 c3 之后；c5 中指向组内 c2 的
引用改指相应副本 c4，指向组外 c1 的引用保留原目标；`next_id` 推进到 5，供后续拆分 / 复制
继续取新身份）：

```json
{
  "order_ids": ["c1", "c2", "c3", "c4", "c5"],
  "clauses": [
    {"id": "c1", "body": "甲方在七日内交付设备"},
    {"id": "c2", "body": "乙方按 [[c1]] 验收后付款"},
    {"id": "c3", "body": "争议解决见 [[c2]]"},
    {"id": "c4", "body": "乙方按 [[c1]] 验收后付款"},
    {"id": "c5", "body": "争议解决见 [[c4]]"}
  ],
  "next_id": 5
}
```

## 谁引用本条接口示例

HTTP 接口 `POST /api/referrers` 接收现有草稿结构（`order_ids` / `clauses`，正文为内部形态
`[[c3]]`）与目标稳定身份（`target_id`），返回该目标的直接引用者（`direct`）与仅经多级引用
可达的间接引用者（`indirect`）；**目标本身不列入**，每个来源只列一次，附稳定身份、当前编号
（`current_no`）及从来源到目标的最短引用链（`chain` 为当前编号序列、`chain_ids` 为稳定身份序列）。
等长链按整条链的当前编号序列取字典序最小，结果按来源的当前顺序排列；重复引用与引用循环
不会造成重复或死循环，失效引用（目标已删除的 `[[cX]]`）不参与遍历。**接口不改正文、顺序、
基线或引用绑定**；目标不存在（或草稿结构非法）时返回 422 拒绝。请求示例：

```bash
curl -X POST http://localhost:8000/api/referrers \
  -H 'Content-Type: application/json' \
  -d '{
    "order_ids": ["c1", "c2", "c3"],
    "clauses": [
      {"id": "c1", "body": "甲方在七日内交付设备"},
      {"id": "c2", "body": "乙方按 [[c1]] 验收后付款"},
      {"id": "c3", "body": "争议解决见 [[c2]]"}
    ],
    "target_id": "c1"
  }'
```

返回（c2 直接引用 c1；c3 不直接引用 c1，只经 c2 多级可达，列在 `indirect`；
`chain` 为“来源 → … → 目标”的当前编号链；无人引用时两个数组均为空）：

```json
{
  "target_id": "c1",
  "target_original": 1,
  "target_no": 1,
  "direct": [
    {
      "id": "c2",
      "original": 2,
      "current_no": 2,
      "chain": [2, 1],
      "chain_ids": ["c2", "c1"]
    }
  ],
  "indirect": [
    {
      "id": "c3",
      "original": 3,
      "current_no": 3,
      "chain": [3, 2, 1],
      "chain_ids": ["c3", "c2", "c1"]
    }
  ]
}
```

## 勾选条款摘录接口示例

HTTP 接口 `POST /api/excerpt` 接收现有草稿结构（`order_ids` / `clauses`，正文为内部形态
`[[c3]]`）与所选稳定身份（`selected_ids`），返回**摘录文本**及各条的**稳定身份（`id`）、
草稿编号（`draft_no`）、摘录编号（`excerpt_no`）**。收录范围为所选条款及其直接、间接引用
（沿目标仍在草稿内的有效引用可达）的全部现存条款，自引用、循环与重复引用只收录一次；
摘录按草稿当前顺序从 1 连续编号，正文中的引用改用摘录内编号，其余字符不变。
**未选择、重复选择或身份不存在返回 422**；收录范围内存在失效引用时整份拒绝（409，
`detail.errors` 逐条列出来源稳定身份与缺失目标，`detail.broken` 为同内容的结构化列表），
范围外的失效引用不阻止摘录。**接口只读**：不改变草稿、基线、身份上界或引用绑定。请求示例：

```bash
curl -X POST http://localhost:8000/api/excerpt \
  -H 'Content-Type: application/json' \
  -d '{
    "order_ids": ["c1", "c2", "c3", "c4"],
    "clauses": [
      {"id": "c1", "body": "合同附件清单"},
      {"id": "c2", "body": "甲方在七日内交付设备"},
      {"id": "c3", "body": "乙方按 [[c2]] 验收后付款"},
      {"id": "c4", "body": "争议解决见 [[c3]]"}
    ],
    "selected_ids": ["c4"]
  }'
```

返回（勾选 c4 自动并入其间接引用的 c3、c2，未被引用的 c1 不收录；引用改用摘录内编号，
如 c4 正文中的 `[[c3]]` 改写为摘录第 2 条的 `[[2]]`）：

```json
{
  "text": "1|甲方在七日内交付设备\n2|乙方按 [[1]] 验收后付款\n3|争议解决见 [[2]]",
  "items": [
    {"id": "c2", "original": 2, "draft_no": 2, "excerpt_no": 1},
    {"id": "c3", "original": 3, "draft_no": 3, "excerpt_no": 2},
    {"id": "c4", "original": 4, "draft_no": 4, "excerpt_no": 3}
  ]
}
```

页面对应操作：勾选条款后点工具栏「导出摘录」，面板展示上表映射与摘录文本，
点「下载摘录」保存为 `excerpt-时间戳.txt`。

## 等待与失败时的行为

所有改动都先发给服务端处理，**只有仍适用于当前草稿的响应才会被采用**：

- **请求在途期间草稿又发生变化**（或已重新导入）时，迟到的响应会被直接丢弃——
  不会把旧列表、旧正文恢复回来，引用跳转也不会拿新顺序去解释旧编号；
  旧请求的失败不会在新草稿上弹出提示或改变按钮状态。
- **预览刷新失败时**（`POST /api/preview` 返回错误、断网等请求异常，或已收到
  HTTP 200 响应头但响应正文读取中断）：页面出现红色
  失败横幅并列出原因，**草稿原样保留、不回滚任何已完成的拆分 / 合并 / 编辑**，
  横幅上始终有「重试预览」；在「预览恢复（返回与当前草稿一致的完整列表）之前，
  条款列表暂停操作、引用不能用旧编号跳转、下载与同步工具栏保持禁用」，预览成功后自动解锁。
  - **刚打开拆分选择器（或编辑器）时预览就失败**：原草稿未改动，卡片操作被暂停，
    横幅除「重试预览」外还提供「取消拆分 / 取消编辑」；取消后即恢复卡片操作
    （重试成功则直接进入拆分选择器，分界可重新选择）。
  - **`POST /api/split` 已成功、随后的预览失败时**：已拆分的正文、顺序、身份与
    引用绑定一律保留，**不会回滚、也不会重复拆分**；列表停留在旧编号期间整体锁定，
    只可「重试预览」。预览恢复后，列表、编号与引用跳转与新草稿一致，可继续编辑、
    重排、合并与再拆分，新身份也不会因重试而重复分配。
  - **预览响应正文读取中断（已收到 HTTP 200 响应头，但正文被截断）时**：与预览失败
    同样处理，**不会误判为成功**——不按残缺响应清空条款列表，已拆分的正文、顺序、
    身份与引用绑定全部保留，页面显示中断原因并保留「重试预览」；恢复前旧编号不能
    跳转、下载与同步工具栏（如「合并所选」）持续禁用。再次「重试预览」若仍中断，
    恢复入口继续保留，可反复重试；只有读到与当前草稿一致的完整预览后，才更新列表、
    引用跳转与下载状态，且重试只重新请求预览、**不会再次拆分**。已有的 HTTP 错误
    （如 4xx/5xx）与断网等连接失败行为不变，同样可点「重试预览」恢复。
  - **拆分请求本身失败**（服务端校验不通过或网络异常）：草稿不改动，已选的分界与
    引用落点保留在选择器内，错误信息显示在卡片上，可直接调整后重试或「取消」；
    断网等异常也会显示失败信息，不会因错误提示处理再抛异常。
- **合并提交期间**（按钮显示「合并中…」，列表置灰）：编辑、删除、↑↓/拖拽重排、
  勾选合并与再次提交都会被暂时阻止；合并成功或失败后自动恢复。
  合并失败不会改动草稿，已勾选的两条保持不变，可修正后重试。
- **拆分提交期间**（确认按钮显示「拆分中…」，列表置灰）：编辑、删除、↑↓/拖拽重排、
  勾选合并与再次拆分都会被暂时阻止；拆分成功或失败后自动恢复。
  拆分失败不会改动草稿，已选的分界与引用落点保持不变，可修正后重试。
- **复制提交期间**（按钮显示「复制中…」，列表置灰）：编辑、删除、↑↓/拖拽重排、
  勾选与再次提交都会被暂时阻止；复制成功或失败后自动恢复。
  复制失败不会改动草稿，已勾选的条款保持不变，可修正后重试。
- **保存 / 导入在途时**，对应按钮显示「保存中… / 导入中…」并忽略重复点击。
- **下载在途时**，「下载纯文本」显示「下载中…」并保持禁用，直到**本次下载自身结束**，
  期间无法重复提交；下载失败（如服务端校验不通过或网络错误）后按钮自动恢复，可直接重试，
  成功保存的文件与当前有效预览一致。
- 下载等待期间**仍允许「重新导入」**：旧下载的成功或失败都会被静默作废——不会保存旧文件、
  不会弹出提示，也不会改变新草稿的按钮状态；待新草稿导入且预览就绪后再次下载，
  新下载在自身返回前始终保持「下载中…」并阻止重复提交。
- 每次改动后到预览刷新完成前，「下载纯文本」「合并所选」和「复制所选」保持禁用，
  保证列表、预览、引用跳转与下载内容始终对应同一份草稿。
- 下载响应返回前草稿若又有改动，本次下载会被取消并提示重新下载，避免保存到与页面不一致的文件。
- 「重新导入」会立即作废旧草稿的全部在途请求（含拆分请求与其后的预览重试）：
  其成功或失败、以及失败横幅与列表锁定等收尾，都不再影响新草稿的提示、按钮与列表。
- **「谁引用本条」是只读查询**：改稿、切换查询目标或重新导入时，旧结果立即清空
  （不置灰保留），面板若仍展开会自动按最新已保存草稿重新查询；在途的旧查询响应一律
  丢弃——既不会恢复旧结果，也不会在新草稿 / 新目标上弹出提示。查询失败（4xx/5xx、
  断网或响应正文不完整）时草稿不变，面板内显示原因并提供「重试」。预览尚未追上最新
  草稿（如预览失败停留在旧编号）期间，不展示基于新编号的引用链，避免与卡片旧编号
  不一致；预览恢复后自动展示。正在编辑正文或拆分选择未结束时，须先**保存或取消**
  才能查看。
- **「导出摘录」同样是只读操作**：结果只对应“某一修订号 + 某一组勾选”——改稿、
  切换勾选或重新导入时旧结果与提示立即清空；在途的旧请求响应一律丢弃，不会恢复
  结果、弹出提示或触发下载。导出期间忽略重复点击（按钮显示「导出中…」）；
  导出被拒绝（如收录范围内有失效引用，HTTP 409）时草稿不变，原因列在摘录面板上，
  修正勾选或修复引用后可再次导出。
- **「保存存档」在途时**（按钮显示「存档中…」）忽略重复点击，但**不阻塞改稿**：
  回执只确认提交当刻的快照，保存期间又有修改的，工具栏仍提示「有未存档的修改」。
  首次保存前的预读取与随后的写入同属发起时的草稿：等待期间**重新导入或恢复存档**的，
  迟到的读取结果（成功或失败）一律作废——不触发写入，也不改变新稿的版本、未存档标记、
  提示或新一次保存的等待状态。
  保存冲突（409）时本地稿保留、不自动覆盖，横幅提供「读取最新版本」入口；
  保存 / 读取失败（断网、响应中断等）时草稿不变，横幅列出原因，可直接再次操作。
- **「恢复存档」须确认替换**：未保存编辑、拆分选择或写稿未结束时按钮禁用；
  恢复在途（按钮显示「恢复中…」）时忽略重复点击，期间重新导入会使迟到的读取结果
  直接作废（不弹确认、不替换新稿）。恢复成功后整份安装并隔离全部旧在途请求，
  自动重算预览与对照；**预览失败保留恢复稿、可重试**，预览恢复前禁止旧编号跳转与下载。

## 写稿提交协调层（合并 / 拆分 / 复制）

前端把合并、拆分、复制三种写稿操作收拢到同一个提交协调层（`app.js` 中的 `submitWrite`），
三个入口不再各自实现请求归属、草稿安装与收尾：

- **协调层负责**：互斥（提交期间阻止其他改稿与重复提交，但允许重新导入）、请求归属
  （世代 + 提交序号：重新导入后，旧请求的成功、错误与收尾一律落空——不改动新稿，
  也不解除新请求的等待状态）、成功写回（正文、顺序与身份上界**一起更新**：
  合并不推进上界、拆分推进 1、复制采用接口返回的上界）、失败归一化与收尾
  （恢复列表与工具栏状态）。
- **入口保留**：本地预检（如条数上限、两段不能只含空白）、参数准备（合并的较前/较后身份、
  拆分的新身份与引用落点、复制的所选与当前上界）、确认弹窗，以及各自的错误展示
  （合并 / 复制弹窗提示，拆分显示在选择器卡片上）。
- **写稿失败**：不改正文、顺序、身份上界与勾选；拆分还保留已选分界与引用落点，可修正后重试。
- **写稿成功后预览失败**：已提交的写稿结果与身份上界保留，不回滚也不重复提交；
  只重试预览（行为详见「等待与失败时的行为」），预览恢复前禁止用旧编号跳转、下载保持禁用。
- 拆分选择器 / 编辑器的「取消」只恢复本地状态，**不发送写稿请求**，也不靠重置页面实现协调。

接口侧不变：三个写稿接口的 HTTP 方法、路径、字段与状态码保持既有约定（见「接口概览」）。

## 操作方式

- **调整顺序**：条款卡片左侧 ⠿ 拖拽，或用 ↑ / ↓ 按钮。
- **合并条款**：勾选恰好两条不同条款（每张卡片左上角复选框，勾选数量不限，但合并须恰好两条），
  点工具栏「合并所选」，确认弹窗中会预览合并后的正文；按当前显示顺序合并，正在编辑正文时不可用。
- **复制条款**：勾选一条或多条条款后点工具栏「复制所选」：按当前显示顺序复制整组，
  副本插在所选最后一条之后，组内引用改指相应副本；正在编辑正文或拆分选择未结束时不可用。
- **导出摘录**：勾选一条或多条条款后点工具栏「导出摘录」：把勾选条款及其直接、间接引用的
  全部现存条款收进一份独立编号的摘录，面板展示「摘录编号 ↔ 草稿编号 ↔ 稳定身份」映射与
  摘录文本，点「下载摘录」保存；正在编辑正文或拆分选择未结束时不可用。
- **拆分条款**：点卡片上的「拆分」，在正文字符之间点击竖线放置分界，选择原指向本条的引用
  落到前段或后段，再点「确认拆分」；「取消」或校验失败都不会改动草稿，正在编辑正文时不可用。
- **编辑正文**：点「编辑正文」，`Ctrl+Enter`（macOS 为 `⌘+Enter`）快速保存。
- **删除条款**：点「删除」（删除被引用条款前会二次确认）。
- **谁引用本条**：点条款卡片上的「谁引用」，在卡片下方内联查看**当前已保存草稿**中
  直接引用本条的条款，以及仅经多级引用（如第 3 条 → 第 2 条 → 本条）才能到达本条的
  间接引用条款；每条来源只列一次，附**稳定身份、当前编号与从来源到目标的最短引用链**，
  等长链按整条链的当前编号序列取字典序最小，结果按来源的当前顺序排列，**链中条款可点击定位**。
  目标本身不列入；重复引用与引用循环不会造成重复或死循环，失效引用不参与遍历；
  没有任何条款引用时明确显示空结果。再点一次「收起引用」（或点面板上的 ×）收起。
  这是只读查询，**不改正文、顺序、基线或引用绑定**；正在编辑正文 / 拆分选择时须先
  **保存或取消**才能查看；改稿、切换目标或重新导入时旧结果立即清空，迟到响应不会恢复
  旧结果或弹出提示；查询失败（如断网）时草稿不变，面板提供「重试」。
- **对照原稿**：点工具栏「对照原稿」展开对照面板，查看相对导入原稿的新增 / 删除 / 正文改动 / 移动；
  再点一次收起。改稿后面板若处于展开状态会自动按最新已保存草稿重新对照，迟到响应不会覆盖新结果。
- **保存 / 恢复存档**：点工具栏「保存存档」把原稿基线、当前顺序、正文与身份上界整份存入服务端
  共享槽；刷新页面或重建容器后，点「恢复存档」（校稿台工具栏或导入页）并确认，即可整份恢复继续校订。
  未保存编辑、拆分选择或写稿未结束时不可恢复；保存冲突时本地稿保留，按提示读取最新版本后再保存。
- 正文中的 `[[n]]` 是可点击的引用标记，点击后高亮并滚动到目标条款。
- 「重新导入」会清空当前草稿，回到导入页。

## 本地开发（不用 Docker）

需要 Python 3.11：

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

存档数据库默认建在工作目录下的 `data/archive.db`（自动创建，已加入 `.gitignore`）；

运行测试：

```bash
pip install -r requirements.txt pytest httpx
```

```bash
node --test tests/test_archive_save_ownership.js
```

## 接口概览（除标注外均为 POST JSON）

| 路径 | 作用 |
| --- | --- |
| `/api/import` | 校验并解析整份导入，错误时 422 + 逐条原因 |
| `/api/save` | 保存一条正文，数字引用按当前显示编号绑定 |
| `/api/merge` | 按当前显示顺序合并两条条款，较后身份并入较前身份，引用统一改指 |
| `/api/split` | 在指定分界拆分一条条款：前段沿用原身份、后段用全新身份，指向被拆条款的引用统一改指所选段 |
| `/api/duplicate` | 按当前显示顺序复制所选一组条款：整组副本插在所选最后一条之后，组内引用改指相应副本；副本取高于所给上界的新身份，返回更新后的上界 |
| `/api/preview` | 返回连续编号、解析后文本及全部失效引用 |
| `/api/export` | 无失效引用时返回纯文本，否则 409 拒绝 |
| `/api/diff` | 入参为基线与当前草稿（均为现有草稿结构），返回新增/删除/正文改动/移动对照及引用失效来源；不回退草稿 |
| `/api/referrers` | 入参为现有草稿结构与目标稳定身份，返回目标的直接 / 间接引用者及最短引用链；只读不改动草稿，目标不存在返回 422 |
| `/api/excerpt` | 入参为现有草稿结构与所选稳定身份，把所选条款及其直接、间接引用的全部现存条款导出为独立编号摘录，返回文本及各条稳定身份/草稿编号/摘录编号；范围内有失效引用返回 409，未选/重复/不存在返回 422；只读不改动草稿 |
| `GET /api/archive` | 读取共享槽存档：返回版本与完整快照（基线、顺序、内部正文、身份上界）；空槽版本为 0、快照为 null |
| `PUT /api/archive` | 携带最近读取或保存成功得到的版本整份写入共享槽，仅版本匹配时写入并加 1；冲突 409（附当前版本），非法快照 422，冲突 / 非法 / 写入失败时旧存档均保留 |
